# 显式裁决：三审 R4.1 / R4.7 遗留项（四审③处置）

> 裁决日期：2026-09-08 · 裁决人：仓库作者 · 性质：显式不做（带理由与
> 风险接受），非沉默漏项——四审 N-③ 点名"未动"，本文件补齐裁决链。

## R4.1（system_secure.launch install 路径）

**裁决：不修，launch 降级为开发态参考。**

理由：生产 launch 谱系已收敛到 NAV2 形态（nav2_localized 等），DDS
security 的 install 断裂只影响 system_secure.launch 一条非生产路径。
修复它 = 为退役路线投入真机验证工时。风险接受：文件头加注记声明
"开发态参考，install 形态已知断裂"（随本裁决落）。

## R4.7（私钥 0600 机制化 + 双 CA 分离）

**裁决：推迟到真机 bring-up 批次，机制化脚本随 keystore 生成工具一并做。**

理由：当前全部验证在仿真域，keystore 的消费场景为零；0600/双 CA 的
修复脚本没有验证场（改了无法证伪）。挂账：真机 bring-up 验收清单
第一项。风险：换机器重建 keystore 会回到 0644——已在本注记留痕，
不构成隐性宣称。

## 附：verify 脚本走 /tmp 自建 keystore 的定性

三审计已认定"绕开而非修复"——维持该定性。/tmp 路径是 CI 可重复性
的权宜（不依赖库内 enclave），**不是** install 路径已修的宣称。
