# ADR：OTA 升级机制（2026-08-24）

> 状态：已接受（v1 决策层 + 模拟层）｜ 对标：JD 职责4「OTA 升级」｜ 单测 7/7 + 三场景模拟实证

## 决策

### 1. 升级决策与物理操作分离

`domain/ota/ota_coordinator.hpp`：纯 Domain 状态机（零 ROS 依赖），槽位物理操作（刷写/原子切标记/回滚标记）以回调注入——**Domain 决策，infra 执行**，与 StampGate 同款分层纪律。

状态机：`IDLE→DOWNLOADING→DOWNLOADED→INSTALLING→SWITCHING→HEALTH_GATE→COMMITTED/ROLLED_BACK`

### 2. 三条安全不变量（单测逐条锁定）

- **I1 活动槽永不被写**：A/B 分区的根基——刷写只指向非活动槽；
- **I2 拒绝先于触碰**：签名/版本检查不过，旧系统毫发无损（测试断言零写入、零标记操作）；
- **I3 未提交即可退**：健康门失败/超时 → 回滚标记 → 重启回旧槽。

### 3. 防降级

安全计数器：`candidate >= security_counter` 才接受；COMMITTED 时计数器前移（挡住刷旧版绕过修复）。

### 4. 升级安全时序（与 ros2_control 生命周期联动，见面试题库 04）

维护模式 → `on_deactivate`（电机进托底/阻尼——手上的鸡蛋不摔）→ supervisor 反序停机（控制器先、硬件后）→ 刷非活动槽 → 原子切标记 → 重启 → supervisor 依序拉起 → `on_activate` 接管语义（命令初值=编码器实际位置——鸡蛋不飞）→ 健康门 → 提交/回滚。

**真值永远从硬件读，不从存储读**：重启后的「当前状态」来自编码器采样（read 先于 activate），不来自持久化记忆。

### 5. 选型（真机阶段）

RAUC（Yocto 主线集成顺、A/B 原生心智、简）优先于 SWUpdate（更可配置但重）；两人团队选简。MCU 侧为同构缩小版：bootloader + app 双区 + 校验签名。

## 增补（2026-08-30）：签名链落地——恒真桩替换（§8.3-2）

审计点名的 `ota_agent_node.cpp` `/*signature_valid=*/true` 恒真桩已替换为
真实 ed25519 验签（`domain/ota/package_signer.hpp`，OpenSSL EVP，纯 domain）：

- **信任模型**：私钥离线（交付侧），公钥烧录设备（`ota.public_key_pem` 参数）；
  签名 base64 随版本送达（`ota.target_signature`），被签对象为规范串
  `amr-ota:v<version>`（防拼接歧义）
- **fail-closed**：签名缺失/错误/公钥未配置 → 验证失败 → coordinator 走
  REJECTED_SIGNATURE——三条安全不变量前的信任门首次真正闭合
- 测试：`test_package_signer`（6 例正反）+ `test_ota_agent` 扩至 4 例
  （坏签名/缺签名/未烧公钥三种拒绝路径，槽位零触碰断言）

交付侧签发示例（与 PackageSigner 同为原始 Ed25519，互通）：

```bash
# 离线私钥签发 v12：
printf 'amr-ota:v12' | openssl pkeyutl -sign -inkey ota_ed25519.pem | base64 -w0
# 设备侧（公钥已配置）：
ros2 param set /ota_agent ota.target_signature <base64>
ros2 param set /ota_agent ota.target_version 12
```

密钥生成：`openssl genpkey -algorithm ed25519 -out ota_ed25519.pem`
（公钥导出：`openssl pkey -in ota_ed25519.pem -pubout`）


## 增补 2（2026-08-31）：信任链收口（三审 P0-D/E/F）

- 验签对象升级为 `{version, sha256, size}` 整体（`image_manifest`）；
  fetch 对实际镜像字节哈希复验——签名绑定内容而非裸版本号
- 公钥出参数域：`ota.public_key_file`（root 属主只读文件），构造期钉住
- install 不再分发 sros2/private 与 enclaves（部署侧独立注入密钥）
- 交付侧签发更新：

```bash
IMG=my_update.img
SHA=$(sha256sum $IMG | cut -d' ' -f1); SIZE=$(stat -c%s $IMG)
printf 'amr-ota:v12;sha256=%s;size=%s' "$SHA" "$SIZE" \
  | openssl pkeyutl -sign -inkey ota_ed25519.pem | base64 -w0
# 设备侧：镜像放 $OTA_IMAGE_DIR/v12.img → set 签名 → set target_version
```
