## 重构前置：现状评估摘要

- **架构**：DDD 四层（hal/domain/infrastructure + observability 横切），传感器独立进程（故障隔离）+ compute 单进程（零拷贝）+ health_monitor 独立
- **量化痛点**：仿真验证环断链——ROS 运行正常但点云不可见、车不动、CPU/GPU 不确认（三个根因已定位：缺 `/cmd_vel` 桥、无 PointCloud2、gpu_lidar + WSL2 死结）；跨进程 trace 未实现（M7 缺口）；metrics 硬编码；HAL 注册表过度设计；看门狗重启同步阻塞；多车未验证
- **健康资产（不动）**：domain/ 全部算法（零 ROS 依赖）、进程拓扑（故障隔离+零拷贝）、降级状态机 + 健康监控闭环、测试体系（98 用例/78.8%）、DDS 双实现可切换
- **确认移除**：ISensor 接口 + SensorRegistry 注册表（sim/real 一致性由 `/scan` 消息契约提供，接口冗余）
- **触发原因**：算法无法在可信仿真中验证——"从能跑到能证明"断在最前一环

## Strategy 终稿

### 一句话定位

**以可信可视化仿真为验证基座的 AMR 巡检 + 算法验证平台** —— 当前阶段本质：把验证环从零重建到能证明算法。

### 核心目标（SMART）

| # | 目标 | 衡量标准 |
|---|------|---------|
| G0 | 渲染层实测 | 装 Vulkan/GL 工具链，确认 ogre2 用 GPU 渲染（D3D12/Vulkan），有日志/进程证据 |
| G1 | 仿真从零重建 | 新 launch：补 `/cmd_vel` 桥 + PointCloud2 + GPU 渲染后端；弃旧 world/桥接 hack |
| G2 | 验证环闭环 | Foxglove 实时点云 + Gazebo 可见运动 + 渲染后端确认 |
| G3 | 单场景闭环 | 车在 sim 巡一圈，感知→决策→执行全程可观察、可复现 |

### 明确的边界（做/不做）

**✅ 做（本期）**
- 环境勘察（渲染层实测）
- 仿真从零重建（弃旧 launch/worlds/SICK passthrough hack）
- 可视化仿真（GPU 路径优先）
- 单场景闭环跑通
- 保留健康资产（Domain 零依赖/进程拓扑/测试体系）
- 移除 ISensor + 注册表

**❌ 不做（本期）**
- 车队 + 多车间调度（远期）
- AI 大脑编排（远期，待深挖）
- 真实硬件部署（以仿真为验证基座）
- M13 可观测性落地（依赖仿真通了之后，下一迭代）
- DDS 深度调优（使用者精通目标，下一迭代）

### MVP 范围

单场景可视化闭环：车在 Gazebo 巡一圈，点云/运动全程可见、可复现。跑通即证明全流程验证可行。

### 成功标准

环境勘察报告 · 仿真重建（`/cmd_vel` 桥 + PointCloud2 + GPU 渲染）· Foxglove 实时点云 · Gazebo 车动 · 单场景端到端录屏 + 验证报告

### 关键假设与依赖

- 假设：WSL2 渲染层能走 GPU（G0 实测，当前工具链未装；CUDA 直通 ✅、/dev/dxg ✅）
- 依赖：Mesa D3D12 / NVIDIA Vulkan ICD · ogre2 后端 · ros_gz_bridge↔Jazzy
- 风险：渲染实测失败 → 无可视化兜底（用户明确偏好可视化），需重新协商；当前概率低

## Operation 规划

| 阶段 | 里程碑 | 交付物 | 预估 |
|------|--------|--------|------|
| P1 环境实测（G0） | M1：GPU 渲染验证 | 渲染层实测报告 | 1-2 天 |
| P2 仿真重建（G1） | M2：新仿真跑起来 | 新 launch + 砍 ISensor，无 hack | 3-5 天 |
| P3 验证环闭环（G2） | M3：点云可见 + 车会动 | Foxglove 点云录屏 + Gazebo 运动录屏 | 3-5 天 |
| P4 单场景闭环（G3） | M4：闭环跑通 | 端到端录屏 + 验证报告 | 2-3 天 |

资源：单人 + AI 辅助，约 2-3 周（重要不紧急）。

### Top 3 风险

| 风险 | 预案 |
|------|------|
| R1：GPU 渲染实测失败 | 排查工具链（Mesa D3D12/NVIDIA Vulkan ICD）；Windows 侧 Foxglove 先验证可视化通道；最坏重新协商 |
| R2：仿真重建引入新问题 | 最小 world + 单传感器先跑通再叠加，一次只动一个变量 |
| R3：DDS 深潜拖 scope | MVP 锁死单场景闭环；DDS 显式排进下一迭代 |

### 验收

- 决策者：自己（面试场景：第三方可复现）
- 流程：M1→M4 逐里程碑门禁确认
- 最终验收物：渲染报告 + 重建代码 + 点云/运动/闭环三份录屏 + 验证报告
